# 世界引擎

SillyTavern（酒馆）第三方扩展。世界引擎维护当前世界变化，记忆引擎整理已发生的剧情和人物认知，剧情大纲提供未来的叙事方向。

当前扩展版本 **3.2.0**，记忆引擎 **1.1.2**，剧情大纲 **2.0.0**。

## 剧情大纲入门

1. 加载本版本后，点击面板标题或悬浮球右下角入口，依次切换世界、记忆和剧情大纲。
2. 进入“编辑大纲”，填写故事方向、约束、章节目标和剧情节点。每个节点可填写意图、完成判据、伏笔或揭示限制，并选择是否必要。
3. 也可在“整理文本”粘贴大纲，或导入 `.txt`、`.md`。启用模块并配置可用 API 后，点击整理，检查预览，再选择采用或继续编辑。整理过程不会直接覆盖已保存的大纲。
4. 在“剧情设置”启用模块。API 默认明确沿用世界引擎配置，也可以选择独立 API；使用 OpenAI 兼容的 `/chat/completions` 接口，支持直连与酒馆代理。
5. 设置“每 N 轮检查”。默认每 **3 个新增对话轮次**检查一次，也可以关闭自动检查，仅使用“立即检查”。

节点会显示待推进、进行中、完成、受阻或跳过，以及引用的原文证据。节点缺少完成判据时，AI 不会自动判定完成。你可以手动指定状态，也可撤销手动覆盖，恢复自动判断。

本章明确设置的退出门槛全部完成或被手动跳过后，会自动进入下一章；没有配置门槛时不会自动下章。旧版大纲迁入时，会把原来的必要节点作为章末门槛。可以手动指定当前章节。AI 提出的改纲建议会显示原内容、新内容、理由和证据，逐条采纳后才生效。

## 跨章节剧情线

章节表示叙事阶段；主线、支线和暗线各自保存节点，章节切换不会结束旧支线。章节退出只检查明确设置的门槛节点，主线终章完成后，其余剧情线仍可继续。

“跨章剧情线”页面可编辑轨道类型、优先级和暂停状态。节点分别配置所属线、适用章节、前置依赖、触发条件、完成判据、正文安全提示与揭露门槛。条件支持全部／任一满足、节点状态、章节、世界实体字段、实际接触线索、剧情时间及作者标记；无法确定时显示信息不足，不把自然语言直接执行为代码。剧情总天数沿用世界引擎解析并提交的时间；日历条件缺少可靠剧情日期时保持等待，不使用电脑日期。跳过节点默认不等于取得物品或满足因果前提。

前台与后台默认各调度最多 3 个节点，每条线每次世界推演最多推进一个节点；等待时间会影响调度机会。“调度与注入”显示选择与等待原因。沿用原有世界请求和大纲批量检查，不给每条线单独增加 API 请求。世界引擎关闭或处于手动模式时，后台暗线等待下一次实际世界推演。

暗线依次区分：幕后事实已发生、线索可以被发现、角色实际接触、形成怀疑或知情。揭露门槛满足也不会直接把完整真相告知所有角色。作者可查看完整幕后进展，正文仅得到允许呈现的安全线索。公共简介、公共约束和节点安全提示应写给正文看的内容；完整作者简介、隐藏身份、意图和备注只作后台指导。

## 三个模块如何配合

- 正文使用当前章和近期节点的柔性指导，保留玩家行动空间，避免一轮完成整章或提前泄露转折。
- 世界推演参考当前目标需要的机会和前置条件，继续尊重已有事实、独立世界变化和人物知情边界。
- 未来计划、节点判断和改纲建议独立保存，不写入人物记忆或事件纪要，也不会直接修改世界事实。
- 首次启用从当前聊天位置开始累计新轮次，不自动批量处理全部历史。已有故事可手动指定当前章和节点状态，或用“立即检查”核对最近 N 轮正文。

正文大纲注入默认以 **2500 字**为目标预算，优先保留当前节点的公开提示、公开约束和可发现线索。单项核心内容超长时完整保留，再省略可选背景；实际长度可在调试中查看。完整远期大纲保留在作者存档中。

## 编辑、重生成和存档

编辑草稿按聊天保留，后台刷新和切换界面不会直接提交或清空。正文重生成、切换回复、修改或删除旧消息后，失效的自动判断会撤回并重新核对，用户手写的大纲和手动状态不会被模型擅自覆盖。

## 联合回退与大量删楼

启用剧情模块后，世界与自动剧情进度使用同一份 v2 联合历史。初始基底、实际状态增量和周期快照与最近几份滚动备份分开保存；默认每 10 次有效世界提交及章节切换生成快照。日志包括已产生的随机结果、冷却、暗线、线索和知情，不通过重掷骰子来恢复过去。

- 同楼重生成：组装提示词前先选择该楼生成前的联合基底，成功后替换本轮分支；取消且原回复仍有效时恢复原分支。
- 删除末尾许多楼：按稳定消息身份、版本和内容核验，恢复最后完整有效提交。
- 删除中间一段：后文即使文字未变，也可能依赖被删的世界基底；不可信的后续结果撤下并标记待重建。
- 一次推演覆盖第 6—10 轮，删除到第 8 轮时，该次推演不能拆成半份；先恢复此前可信状态，保留的第 6—8 轮需要重新对账。
- 回忆、倒叙、梦境或返回旧地点不会自动撤销现实进度；不明确的时序问题只提示核对。

恢复页显示边界、提交、撤回或等待重建的原因。没有对应历史、删到启用基底之前或聊天与存档不配套时，暂停未核验状态的注入，提供备份恢复和“显式批量重建”。重建按保留正文调用模型建立新分支，不声称重现缺失的原随机历史；中止后保留已完成批次。大量删除不会自动启动大批付费请求。

从头重建时，缺少消息来源的旧记忆、旧手动快照和摘要先完整备份，再退出当前记忆投影，防止删掉的剧情经旧记忆重新进入正文。恢复页可导出这份备份供作者复核；大纲和作者手动覆盖保留。

v2 使用独立状态和聊天命名空间，只在首次读取时迁入 v1。原 v1 数据保留；未知更高版本拒绝写入。旧设备修改了兼容世界状态时会标记基底变化，需恢复联合备份或显式重新建立基准。跨聊天导入只带静态计划，清除旧世界执行、进度、知情和来源。

“存档与导入导出”支持：

- 大纲 JSON：只含计划，便于复用。
- 完整 JSON：包含计划、进度、证据及联合日志；同聊天可明确选择恢复进度，跨聊天默认清零。
- 命名快照、恢复、重命名、导入导出和删除；恢复前自动保留一份备份。
- 可选聊天同步和滚动自动备份，默认关闭。同步依赖酒馆保存的同一份聊天，不包含 API Key 等全局设置。

“调试”可查看最近请求、响应和最终提示词注入状态，并导出脱敏诊断。剧情模块默认关闭；API 未配置时仍可手工编辑、存档，并在启用后使用已有大纲引导。

## 运行与验证

本扩展依赖 SillyTavern 提供的聊天事件、提示词注入、世界书和聊天元数据接口。需要通过支持第三方扩展的酒馆加载本仓库代码；无需 npm 构建。模型推演、文本整理和进度判断会产生额外 API 请求。

离线回归使用 Node.js 内置模块，无额外依赖。在 PowerShell 中运行：

```powershell
$failed = @()
Get-ChildItem -LiteralPath docs -Filter '*test.js' | ForEach-Object {
  node $_.FullName
  if ($LASTEXITCODE -ne 0) { $failed += $_.Name }
}
if ($failed.Count) { throw ($failed -join ', ') }
```

离线测试使用真实模块和模拟的酒馆／模型接口。实际模型的因果判断、对大纲的遵循程度以及酒馆版本兼容性仍需在运行环境中验证。
